# Criterios operativos

## Contratos de soporte (Chile)

- Para propuestas o contratos de soporte, presentar primero el texto completo en el chat para revisión del usuario antes de crear una versión final en archivo.
- Cuando corresponda, usar un formato formulario para los datos del cliente y describir explícitamente alcance, tarifa, horas incluidas, facturación, mora, suspensión, propiedad/entrega y término.
- En formularios contractuales, los datos permanentes del Prestador deben quedar fijos; solo deben ser editables los datos que realmente deba completar el Cliente. Los canales operativos y referencias PAC/PAT se informan oportunamente y no necesitan campos contractuales.
- Para documentos de Prof3sional Core 360, preferir una presentación limpia y formal, con fondo blanco y acentos de marca; evitar fondos negros o una apariencia de aplicación.
- En contratos preparados para Adobe Sign, no usar cajas, rellenos ni campos visibles tipo interfaz. Dejar líneas discretas para datos y firmas, para que Acrobat Sign superponga sus campos de firma al enviar el documento.
- Para contratos comerciales de pago anticipado, Carlos prefiere usar Adobe Acrobat Sign con firma electrónica simple y trazabilidad, salvo que un caso posterior exija firma electrónica avanzada o intervención notarial.
- En contratos de soporte, mantener el cuerpo simple y usar un anexo de matriz de horas referenciales en décimos para limitar solicitudes repetitivas. La garantía debe restringirse a errores de implementación que alteren una funcionalidad entregada, excluyendo cambios estéticos, preferencias o solicitudes posteriores.
- Para sitios desarrollados por Prof3sional, el Cliente debe conservar acceso de propietario al repositorio GitHub, mientras que Vercel, Supabase y Cloudflare R2 permanecen bajo administración exclusiva de Prof3sional. Al término, los activos se entregan sin traspasar cuentas o credenciales de infraestructura.
- En contratos de soporte B2B, precisar que el precio anual en pesos corresponde a 1,5 UF redondeadas hacia arriba al millar y queda fijo durante el período anual; la renovación es la instancia de actualización. Incluir sin alargar innecesariamente: rechazo PAC/PAT no extingue la deuda, no hay SLA implícito, garantía solo para defectos de implementación, y límite de responsabilidad por daños directos salvo dolo, culpa grave o materias indisponibles.
- Cuando el Sitio trate datos personales o publique contenido aportado por el Cliente, establecer que este declara contar con derechos, autorizaciones y base de licitud; Prof3sional conserva sus propias obligaciones de seguridad y confidencialidad. Una indemnidad del Cliente debe excluir los hechos imputables al Prestador.
